# Monorepo release and publishing

npm publishing remains disabled (`NPM_PUBLISH_ENABLED=false`). No HAOS deployment is configured.

Each package is registered in `packages.json`. Run package checks with `PACKAGE_NAME=NAME node tools/verify-pack.cjs`; install/test/audit from its package directory. CI currently covers debug-file on Node 22 and 24. When adding a package, expand both test and audit matrices, explicit publish choices, Dependabot and required protection checks. Keep development files out of tarballs.

Tags are `NAME/vX.Y.Z`. Release assets are the package tarball and SHA256SUMS. Use `PACKAGE_NAME=NAME node tools/release-github.cjs OWNER/REPO TAG ARCHIVE NOTES` only after explicit authorization, successful security checks, and pushing a new immutable tag. The tool checks every archive byte against the tagged package and downloads the upload to verify its hash. Never overwrite tags, versions or assets; inspect remote state after ambiguous mutation failures.

v0.2.0 retains its historical manifest and six-file tarball semantics. It lacks repository provenance metadata and cannot pass npm preflight. A future separately authorized version must add repository URL `git+https://github.com/Deluka-BE/custom_nodes.git` and directory `packages/NAME`, plus appropriate homepage/bugs/publishConfig metadata. Never modify v0.2.0 assets to add metadata.

For future npm publication, the user must verify npm ownership interactively, configure trusted publisher for Deluka-BE/custom_nodes, workflow publish.yml, environment npm-NAME, and configure NPM_OWNER in that environment. Enable both repository NPM_PUBLISH_ENABLED and the per-package NPM_PUBLISH_NODE_RED_CONTRIB_DEBUG_FILE_ENABLED switch only after separate publication authorization. Both remain false now. Add a distinct package switch when expanding publish choices. Configure approval reviewers and only NAME/v* tag deployments for every package. Dispatch from the exact immutable release tag with exact package confirmation. Validation has no OIDC; only the approved publish job requests id-token, publishes the verified GitHub archive once with provenance, and has no tokens, lifecycle scripts or retries. Missing registry ownership, existing versions, absent protections or unavailable metadata fail closed. Bootstrap publication needs separate authorization.

`node tools/configure-github.cjs Deluka-BE/custom_nodes Deluka-BE` configures the initial debug-file environment, main protections, immutable package tags, secret scanning and alerts. One required PR approval needs another collaborator; self-approval is unavailable. Report API restrictions without weakening guards.

Lex currently has working gh authentication. A deploy key is unnecessary. If dedicated SSH access is later needed, use a single key scoped exclusively to this repository, read-only unless push is required. A deploy key cannot replace API permissions for releases/settings. Generate and store private material locally only with separate need/authorization; never commit or expose it.
